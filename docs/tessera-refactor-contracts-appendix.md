### Gotchas

- Defaults are RUNTIME fallbacks, not struct initializers: none of ts_dartquant_params / ts_champq_params / ts_lrq_params / ts_flrq_params / ts_septq_params has in-class initializers. Zero-initializing gets you: lrq rank=0 -> return -1; septq septq_ratio=0 -> return 2, ternary_threshold=0 -> return 4 (SEPTQ applies NO runtime defaults at all -- strict validation only). The '<=0 -> default' fallbacks exist only for: dartquant {block_size, max_iters, lr}, champq {max_iters, sinkhorn_iters, history}, lrq {max_iters, lr, tol, seed}, flrq {all fields}. tessera-awq.h:151-157 documents the shipped bug that motivates the initializer-invariant on ts_awq_evolve_params -- the seam's eval_opts struct must follow that invariant.
- SEPTQ septq_iterations is a phantom knob: validated (>=1 else return 3) at tessera-septq.cpp:447 and then never read -- the C++ port does exactly one mask pass. Do NOT scale the eval cost model or the cache key semantics by it (but DO include it in the cache key hash anyway since the Python reference iterates).
- SEPTQ ridge floor swallows the documented default: effective ridge = max(ridge_fraction, 1e-2) * diag_mean (cpp:95), so the documented ridge_fraction default 1e-4 -- and any value < 1e-2 -- produces identical Hessians. Cache keys over ridge_fraction values below 1e-2 are all equivalent.
- SEPTQ 'outliers' are the UNIMPORTANT elements (mask_flat == 0, i.e. the complement of the top-ceil(n*septq_ratio) importance set), stored at f16 from the error-COMPENSATED W_comp = W - E@M -- not the usual 'salient outliers' convention. Outlier count ~ (1 - septq_ratio) * out_dim * in_dim; small septq_ratio means the CSR arrays dominate memory (~8 bytes/outlier).
- Scales asymmetry: page_scales/lane_scales are computed against the ORIGINAL weights (mean|W| over nonzero-ternary lane entries), while outlier_vals come from W_comp (cpp:685-690 vs 672). A scoring adapter that reconstructs from packed data reproduces exactly what inference sees; recomputing scales from W_comp would diverge from the on-disk format.
- with_meta argument contract: lane_scale_in must be f32 ALREADY divided by 127 and page_max_in already f16->f32 decoded (ggml-quants.c:384-387). Passing ts_septq_result.lane_scales (int8) or page_scales (uint16 bits) raw is garbage. ts_decode_per_row_meta does both conversions for the whole tensor in one call. The flat dequantize_row_tessera_t640 instead wants a single contiguous per-row [words|page_scales|lane_scales] buffer -- ts_septq_result stores the three arrays SEPARATELY (tensor-global, row-major), so the flat variant needs a repack while with_meta needs only pointer slicing.
- Row slicing of ts_septq_result for the adapter: pages_per_row = (in_dim + 639)/640; row r's packed = &packed[r * pages_per_row * 32] (pages_per_row*32 uint32 words); page meta slice = &page_max[r * pages_per_row]; lane meta slice = &lane_scale[r * pages_per_row * 32]; pass k = in_dim. Encoding is bit-compatible: SEPTQ packs word = sum digit_s*3^s (s=0..19), dequant decodes 4 radix-243 groups of 5 trits -- identical positional base-3 (243 = 3^5). Trit map both sides: {0,+1,-1} <-> digit {0,1,2}; dequant: trit==1 -> +scale, trit==2 -> -scale.
- ts_apply_outlier_addback ASSIGNS (rows[r][col] = f16val, ggml-quants.c:607), it does not add. This is safe only because ternary is exactly 0 at every mask==0 position (ternary = (mask & keep) ? sign : 0), so the dequant wrote 0.0f there. If a future format overlaps outliers with quantized positions, the assign semantics silently drop the ternary contribution. It reads base = offsets[0], so passing an offset sub-slice for a row range works.
- lane_scales clamp to [1,127] means an all-zero lane still decodes to nonzero scale (lane_target 0 -> raw 0 -> clamped to 1 -> scale = page_max/127), but all its trits are 0 so y stays 0 -- harmless for reconstruction, relevant only if a digest normalizes 'empty' lanes.
- dequantize_row_tessera_t640_with_meta zero-fills the trailing portion of the LAST page only up to TILE640_PAGE_SIZE and writes only page_len outputs -- y needs exactly k floats, not padded-page floats; but packed/meta must cover full ceil(k/640) pages including the padded tail.
- SEPTQ banded mode silently downgrades to diagonal when activations == nullptr (cpp:454-457) with NO error/flag in the result; in diagonal mode M is identically zero so W_comp == W. A cache key that records hessian_mode as-requested (not as-executed) will alias two different results across calls that add activations later.
- Precision regimes differ per expert and will show up in cross-backend digest mismatches: dartquant promotes EVERY matmul to f64 dgemm with per-call heap copies (cpp:80-151) -- both a cost driver and a parity guarantee; champq/flrq/septq(E@M) use f32 sgemm; LRQ uses no BLAS at all (naive scalar triple loops). The two ts_ternarize_recon copies disagree: dartquant.cpp:47-53 accumulates mean|x| in double, lrq.cpp:9-15 in float -- unify carefully, the f64 version is the numpy-parity one.
- LRQ wastes one full matmul per iteration: cpp:151 computes dU with wrong operand interpretation, then 155-163 recomputes it correctly; the first result is discarded but the O(out_dim*in_dim*rank) cost is paid. Also both LRQ and DartQuant report n_iters = max_iters even on early convergence (lrq.cpp:196, dartquant.cpp:457) -- n_iters is NOT the actual iteration count and must not feed a cost model or cache key as 'work done'.
- DartQuant returns the FINAL rotation, not the best-seen (best_R tracked then (void)-discarded, cpp:440-448), matching Python; result.R is (K x K) with K = block_size (or in_dim when 0) -- the struct comment '(in_dim x in_dim)' (h:22) is wrong for block_size > 0. ts_dartquant_apply tolerates in_dim % block_size != 0 by copying remainder columns verbatim, despite h:71 claiming divisibility is required.
- CHAMP-Q binariness: header (h:41) says 'Default 1e-3, matches champq_permute.py CLI default' but ts_champq_compute uses the raw value (comment '0 by value-init', cpp:373) -- a value-initialized params gives 0 (penalty disabled). The seam must set 1e-3 explicitly for Python parity. Also: projection=0 (Hungarian) is silently overridden to greedy when K > 512 (cpp:466); seed only matters for init==2; loss_history is empty when use_lbfgs == false.
- CHAMP-Q per-iteration eval count: each L-BFGS iteration runs up to max_ls=12 line-search evals (ts_lbfgs_step_params {1e-4f, 12, 0.5f, 1e-12f}, cpp:437) PLUS one mandatory re-eval at the Sinkhorn-projected point (cpp:451); it never stops early on line-search failure (cpp:454-459). Each eval = 2 sgemms of (out_dim x K x K) + O(out_dim*K) stencil; each projection = sinkhorn_iters * O(K^2). M is a dense K x K = in_dim^2 f32 buffer -- 64 MB at in_dim=4096; this is the memory cliff for champq on large tensors.
- FLRQ always pays a final recompute: ts_train_flrq re-runs sketch+BLC at the chosen rank even when the sweep's first candidate cleared (cpp:344-356), so minimum cost is 2x(sketch+BLC). Per-rank sketch seed is seed + r (cpp:320/346) -- the cache key needs (seed, rank) jointly, not seed alone. Sketch RNG (xoshiro128** Box-Muller) is deterministic but NOT bit-identical to numpy PCG64 -- digests must carry an implementation/version tag, not just parameters.
- FLRQ ts_flrq_bcl_result.U duplicates the input basis and residual/residual_q are full K x N f32 buffers -- a result cache that stores whole ts_flrq_bcl_result entries pays ~3x tensor size per entry; cache the digest + MSE, not the buffers.
- Thread-safety contract at the seam: ts_awq_evolve_params.eval_recorder is invoked from inside the parallel eval_population (must be thread-safe, h:227-232); the evaluator ctx is shared across layer threads when n_threads > 1 (h:188-189). An eval_cache memoization layer wrapping ts_expert_eval sits exactly on this hot path and must be lock-sharded or append-buffered, mirroring the documented Appender pattern.
- Units/conventions everywhere: weights row-major f32 (out_dim x in_dim); activations (n_tokens x in_dim) rows; page_scales are raw IEEE-754 f16 BIT PATTERNS in uint16 (never a half type); lane_scales int8 in [1,127]; packed words uint32; champq perm is 'W_perm[:, j] = W[:, perm[j]]' (gather, not scatter -- ts_champq_invert converts); dartquant convention W_rot = W @ R.

### Gotchas

- ga_weight_loaders MUST be reserved before the ga-prep loop (FILE:2129) — layer.weights_user_data stores a raw pointer to ga_weight_loaders.back() (2256-2257); any realloc dangles every prior pointer and SIGSEGVs GA workers inside the weights_load_fn lambda (comment 2251-2255).
- Lifetime coupling: cluster_results / moe_results are std::deque (stable element addresses, 2634-2635). GGUF descriptors hold raw data pointers into them and gguf_write_to_file (3873) reads through those pointers AFTER the walk, the L5 loops, and acceptance. refine_map entries carry qr pointers into cluster_results (3167); the L5 loop re-quantizes in place through those pointers and must call ts_gguf_repoint_tensor_cluster (1465) because ts_quantize_2d may reallocate the vectors. Any module split must keep the deques alive until step 9 and preserve the qr aliasing.
- The input GGUF mmap is intentionally leaked: fd closed right after mmap (1950), no munmap anywhere; every ggml tensor's data points into the mapping (1954-1961). ts_refine_reread_source, the acceptance workers, and the GA weight loaders all re-read via ts_tensor_to_f32 from this mapping across the whole run. The comment at 1962-1966 mentions storing it in a static, but no static exists — do not add cleanup that unmaps before step 9.
- l4_plan_outcome column list (877-889) must match BOTH the CREATE TABLE and the 19 values ts_tessera_db_append_l4_outcome pushes, in order. Historical failure: Phase 16 added model_role to struct+helper+table but not this list; every flush became INSERT(18) VALUES(19) and silently dropped the run's entire L5 feedback record (90/90 rows).
- ts_dispatch_awq_eval streaming path: ts_quant_result_2d qr is declared but only populated when kernel-direct is ON (328); yet score.mse and score.heldout_mse are assigned from qr.mse (418, 420), not from the streaming mse_val — on the default path the ga_evaluations mse column therefore carries qr's default-initialized mse, not the measured one (composite is correct: -t2 from mse_val, and the B2 override replaces mse when second_moment is present). Preserve-or-fix knowingly when building ts_expert_eval.
- ts_dispatch_forced_t2 ignores its outlier_thresh and seed parameters (444-464): the expert profile influences the score ONLY via prof.alpha_scale/clip_scale through the same T640 streaming core. This is precisely why the G6 per-method scores could not disagree (rotation and Hessian bit-identical to AWQ on 197/197 Orpheus tensors, comment 521-526) and why tier2_t2 exists.
- Acceptance hessian_t2 is NOT a Hessian measurement: it is ts_dispatch_forced_t2(..., TS_EXPERT_SEPTQ, ...) (3710, 3765) — a profile-scaled AWQ-core proxy. SEPTQ Tier-2 scoring is unimplemented (tier2_t2 default returns -1, 610-612) because it needs a dequant of SEPTQ's packed output (comment 537-539) — the seam's dequantize_row_tessera_t640_with_meta plugs exactly here.
- kernel_direct_t2 falls back to at.composite_t2 when no sidecar exists (3724-3728, 3772-3776), which makes the G6 ranking-disagreement test vacuous in that configuration — a real sidecar dir (params->kernel_fitness_dir or $LLAMA_TILE640_DEBUG_DEQUANT_DIR) is required for a meaningful kernel-direct verdict.
- Acceptance-prep routing can differ from walk routing for the same tensor: the prep walk computes the regime descriptor with NO imatrix data (nullptr, 0 at 3658-3659), while the step-7 walk passes imatrix stats (2763-2765). Also, acceptance ignores GA/policy alphas — it uses default_alpha and params->awq_clip (3601-3602).
- The OBQ omega loop (3281-3293) indexes weights and qr.recon as w[r*out_dim + c] with r over in_dim — a transposed view of the row-major (out_dim rows x in_dim cols, ne[0]=in_dim fastest) layout used by every other consumer. It covers all n elements so the total error is right, but the pairing of row-sums with hinv[r] assumes input-channel-major rows. Verify intent before porting into the seam.
- Auto-sizing block comment says 'Budget ~1.5 GiB' (2397) but the code uses 3 GiB (2426: (int64_t)3*1024*1024*1024). Trust the code, and know parallel layers weaken same-family warm-start propagation (comment 2401-2405).
- The mm_awq map is written by ga-prep (2192-2195) AND lazily extended by the step-7 walk (2790-2798); mm_modality is written only in ga-prep but is read concurrently by GA eval threads via eval_ctx.modality — safe today only because ga-prep fully populates it before ts_awq_evolve_all starts. A module split must not interleave those phases.
- Thread-safety: ts_dispatch_awq_eval runs on GA eval threads — the sharded maps (sidecar_cache with_lock lazy load 364-392, best_t2/best_pair 405-416) exist because a plain unordered_map races on rehash across different keys; mode_prints is a relaxed atomic log-rate cap. Acceptance forced_t2/tier2_t2/kernel_direct_t2 run on a work-stealing pool (atomic next_idx, 3749-3752). The eval seam must stay reentrant and allocation-bounded (streaming MSE = ~132 KB scratch vs ~700 MB for full ts_quantize_2d, comments 320-325, 454).

### Gotchas

- Null-DB convention: every write helper returns 0 (success no-op) when db/conn is nullptr; readers return false/empty. h:17-19 documents it and read/write_hessian_cache re-state it. eval_cache helpers must keep this or the null-guarded dispatch paths break.
- No prepared statements anywhere: all SQL is string concatenation + sql_escape (single-quote doubling only). write_hessian_cache deliberately uses a string BLOB literal to keep the materialized Query() overload (RowCount() exists) instead of the parameterized API which returns base QueryResult (cpp:2926-2930 comment). Copy that choice for eval_cache blobs/digests.
- DuckDB amalgamation has NO core_functions: CURRENT_TIMESTAMP/NOW() unavailable (timestamps are C++-formatted quoted literals via ts_now_ts, cpp:635-651,703-707) and SUM/AVG unavailable (l5_outcome_stats_for uses COUNT(*) FILTER + C++ ratio, cpp:1276-1316). eval_cache aggregates must do the same.
- Templated QueryResult::GetValue<float>(col,row) truncates through int64_t; must fetch duckdb::Value then .GetValue<float>() (cpp:1727-1732 and 1812-1814 comments). Any eval_cache reader returning floats must follow this.
- ON CONFLICT DO NOTHING conflict detection: DuckDB reports RowCount()==1 for the skipped insert, so *stored requires the pre-count SELECT BEFORE the INSERT (cpp:2957-2976). The pre-count is racy under concurrency -- the comment says the hessian path is single-threaded. ts_expert_eval with parallel per-expert workers must serialize eval_cache writes or treat *stored as advisory (first row is still permanent either way).
- l4_cols drift bug class (dispatch.cpp:875-884): Phase 16 added model_role to the struct + append helper + CREATE TABLE but not the dispatch column list; every flush became INSERT(18 cols) VALUES(19 values) and failed, silently dropping the run's ENTIRE L5 feedback record (observed 90/90 rows). THREE places must agree per buffered table: CREATE TABLE string (quantize-db.cpp:354-375), value order in the append shim (quantize-db.cpp:1592-1613), and the caller's column vector (dispatch.cpp:882-889). Failure is silent-ish: stderr + rows_dropped, never an error return to the producer.
- Buffer guards are two-layer: append drops a single row on values.size()!=column_names.size() (buffer.cpp:70-77); flush drops the WHOLE batch on any SQL error (buffer.cpp:245-278). Neither propagates to the producer; check ts_db_buffer_stats_get().rows_dropped at close (dispatch.cpp:918-940 does).
- ts_db_buffer flush emits plain 'INSERT INTO t (cols) VALUES (...),(...)' with NO ON CONFLICT clause (buffer.cpp:228) -- a PK-conflicting row poisons and drops its entire batch. Therefore eval_cache first-write-wins writes CANNOT go through ts_db_buffer as-is; use the direct hessian-style helper, or extend the buffer with an on_conflict suffix option.
- Stale doc: tessera-db-buffer.h:69-70 claims the buffer 'takes a reference to column_names (does not copy)'; the impl ctor takes the vector by value and moves it into a member (buffer.cpp:51-63) -- it does copy, so passing a temporary is safe.
- Buffer value protocol: literal string "NULL" means SQL NULL; empty string means quoted '' (looks_like_int/float return false for empty, buffer.cpp:287-308); numerics must be plain std::to_string output (an accidental leading space would get quoted as text). durable parameter is stored but never used -- no fsync path exists.
- The buffer does NOT own ts_tessera_db (buffer.h:31-34); every buffer must be ts_db_buffer_close'd before the DB is deleted -- dispatch.cpp:905-941 is the ordering reference. The DB destructor issues a best-effort CHECKPOINT (cpp:659-683); SIGKILL/jetsam leaves a .wal that blocks the next read-only open.
- TS_QDB_SCHEMA_SQL is NOT the full live schema: l5_outcome's kurtosis/eff_rank/layer_position columns exist only via the ALTER TABLE migration (cpp:2484-2488). Any column-list generation from the CREATE strings would be wrong for l5_outcome; information_schema is the only accurate source.
- New tables that ship with model_role from day one (v2_hessian_cache, imatrix_accum_state, regime_*, l5_search_state) are NOT added to the 7-table Phase-16 migration map (cpp:2216-2422). eval_cache and kv_stats must follow that precedent -- do not touch the migration map.
- Hessian JSONL ledger's "ts" value embeds ts_now_ts()'s single-quoted literal, producing {"ts": '2026-08-13 ...', ...} -- not strict JSON (cpp:2803-2804). Consumers must tolerate it; an eval_cache ledger copying the pattern verbatim inherits the quirk (fix consciously or keep for consistency). Ledger calls inside read/write pass nullptr err, so ledger I/O failures there are fully silent.
- ga_evaluations has NO primary key (append-only duplicate-tolerant log). eval_cache is the opposite: it NEEDS the PK for ON CONFLICT DO NOTHING. Do not model eval_cache on the ga path.
- ts_tessera_db_migrate_model_role is declared twice in the header (h:231-233 and h:512-513) -- harmless duplication, but don't triple it when appending eval_cache declarations.
- Empty model_role is normalized to 'trunk' inside every writer (e.g. cpp:1002-1004, 1589-1591); readers default NULL model_role to "trunk" (cpp:1234-1239). The hessian read/write does NOT normalize (passes model_role through verbatim, cpp:2848-2849, 2946) -- an empty-string role would silently key a separate cache row; ts_expert_eval should normalize before calling.
- Migration map iterates a std::map => alphabetical table order, not the documented 'leaf tables first' (comment admits order is not enforced, cpp:2211-2215). ":memory:" DBs get no sidecar and no ledger (cpp:2115, 2787-2789).

### Gotchas

- Sign conventions are OPPOSITE across the two subsystems: the GA maximizes ts_awq_score.composite (rank descending, update_best uses >, one-shot accept uses >=), while the acceptance gate minimizes t_l^2 (composite_wins = composite_t2 < best_single_t2 * (1 - margin), best_single = min-fold). A ts_expert_eval seam feeding both must not flip either.
- ts_awq_evolve_params carries a hard invariant (tessera-awq.h:150-157): EVERY field must have an in-class initializer. A bare seed_candidate pointer once read garbage-non-null and bred garbage genes into winners, breaking test_awq determinism on main. Any new eval_opts/seam field added to this struct must be initialized in-class.
- eval_recorder is called concurrently from eval_population worker threads whenever n_eval_threads > 1 (and additionally from multiple layer GAs when evolve_all n_threads > 1); it MUST be thread-safe (buffer into a per-call Appender). It receives generation = -1 for the initial population — DB consumers must accept -1.
- eval_ctx is shared across all layer threads in ts_awq_evolve_all; the GA does not guard it — the caller must (the dispatch ctx carries its own mutex for the sidecar/best-t2 caches). Same for the on_layer_done callback (must be thread-safe).
- evaluations counting: the std::atomic evaluations counter increments once per eval() call inside eval_population, and the one-shot seed test reports evaluations=1 without going through eval_population (so it is NOT streamed to eval_recorder — a cache/DB layer hooked only on eval_recorder will miss the seed-hypothesis evaluation at tessera-awq.cpp:269).
- Post-fix generation semantics: elites (top 25%, min 2) keep the scores they already earned and are NOT re-evaluated or re-recorded; only newly-bred children are evaluated, in ONE eval_population call per generation spanning all islands (gen_tasks). Pre-fix, 77% of 601,920 evaluations were within-generation duplicates. Any memoization layer must not reintroduce per-elite re-scoring, and per-generation recorder row counts equal children only (pop - elite_count per island).
- Velocity gate wiring is two-phase: vgate seeded with the initial best BEFORE the loop (add at tessera-awq.cpp:403), one add per generation after migration (:514), break sets converged=true; AND a separate natural-exit rule (:536-539) marks converged when all generations ran but |vgate.velocity()| < velocity_threshold with >=2 scores (covers evolve_iters=8 with stagnation_limit=10 where the window can never fill). generations_run = gen + 1 even on early break. stagnation_limit default is 0 (off) in the struct — the dispatch is responsible for setting the real default.
- One-shot accept preconditions are threefold: seed_candidate != nullptr AND seed_composite > 0.0f AND seed_accept_ratio > 0.0f. Warm-start injection (pops[isl][1] = seed, member 0 stays random) happens in EVERY island regardless, whenever seed_candidate is non-null; warm_started is set from seed_candidate != nullptr even if the seed lost.
- layer_skip_lookup resume is guarded by `(*results)[i].best.genes.alpha == 0.0f` — it relies on results->resize() zero/default-initializing entries (alpha's in-class default is 0.0f); a pre-populated results vector suppresses the skip.
- ts_acceptance_mean_field uses raw byte offsets computed by pointer arithmetic into ts_acceptance_tensor (tessera-acceptance.cpp:84-88); reordering or inserting fields in ts_acceptance_tensor silently changes which column is averaged.
- The two kendall computations differ in population: Test 2 (gating) uses ONLY held-out tensors and needs m >= 2 (else tau_min stays 1.0 and novelty fails at disagreement 0); the v1 kernel-fidelity diagnostic uses ALL n_tensors including training ones.
- Test 2 keeps the tau with the SMALLEST |tau| across the 6 method pairs (most-disagreeing pair) so one degenerate slot — e.g. a score column still carried by a proxy — cannot suppress signal; the verdict string still brands hessian as "hess=%.6g(proxy)" (tessera-acceptance.cpp:167), the marker that SEPTQ Tier-2 is not yet real.
- Uninitialized-field traps outside evolve_params: ts_awq_candidate.expert_hint, all four ts_awq_score fields, and every ts_awq_layer pointer/dim except layer_depth have NO in-class initializers — value-init ({} or resize) is required; ts_awq_evolve_all takes layers NON-const and temporarily mutates layers[i].weights during streaming load (weights is nulled after release, so the array is not reusable for a second pass without reloading).
- Streaming-weights ownership: weights_load_fn's returned buffer is caller-owned and must stay valid until weights_release_fn; when weights_load_fn is null, weights must be pre-loaded. The one-shot/skip path via layer_skip_lookup never touches weights (no load/release).
- ts_awq_evolve clamps population to >=2, generations to >=1, islands to >=1, migration_interval defaults to 10 when <=0 — the effective values may differ from what the params struct says.
- Determinism: xorshift32 seeded per layer as params->seed + (uint32_t)layer_index (screen: + screen_li[si]); breeding RNG is single-threaded (only eval fan-out is parallel), so results are deterministic for fixed seed regardless of n_eval_threads; but in evolve_all with n_threads > 1, WHICH family seed a layer sees depends on thread completion order (documented as acceptable: both are near-optimal).

### Gotchas

- MSE-parity claim in the header is STALE post tile-neutral refactor: tessera-quant.h:186-190 says ts_quantize_mse_streaming 'matches ts_quantize_2d's' MSE, but nothing ever populates ts_ternary_tensor.core (only reads at cpp:1163-1166; ts_quantize_2d_ternary explicitly skips it, cpp:1078-1080), so ts_quantize_2d always takes the core==nullptr global_amp-uniform scale fit in ts_pack_ternary_to_tile, while the streaming path fits per-element |row_core| magnitudes (cpp:1444-1447). test_t640_core_reconstruct_parity.cpp pins the two fits at <=1.5x L2/L_inf of each other and asserts they are NOT bit-identical. An eval_cache keyed on (model_hash, model_role, name) must therefore record WHICH scorer produced the number (streaming vs full-path), or Tier-2 scores and final quantize_2d MSEs will silently disagree.
- alpha=0 means two different things: in ts_quant_params_2d.alpha, 0 = auto-search (grid search runs when act_scales present, cpp:987-1024); in ts_quantize_mse_streaming's alpha argument, 0 = no AWQ scaling, taken literally, never searched (cpp:1382-1384). The eval seam must resolve alpha (via genes or a prior search) BEFORE streaming scoring.
- ts_quantize_mse_streaming has no outlier parameters: it never selects or restores repair residuals, so it equals the full path's MSE convention only when max_outliers==0. ts_quantize_2d's MSE restores outlier positions to exact ws values before the fold (deqrow[col]=wsrow[col], cpp:1307-1314), giving zero error at outliers; genes that vary max_outliers/outlier_thresh CANNOT be differentiated by the streaming scorer.
- Clip semantics are strictly open-interval: clip is active only when 0 < clip < 1 (checks at cpp:288, 1427); clip=0 AND clip>=1 both mean 'no clip' (the defaults literal uses clip=1.0f = inactive, cpp:966/1204, while the header field comment says '0 = none', h:141). Clip shapes ONLY the ternary codes (applied to core/row_core); the MSE reference is always the UNCLIPPED scaled ws — measuring against clipped values would score aggressive clips optimistically (h:188-190, cpp:1404-1409).
- MSE domain vs recon domain: result->mse and the streaming return are measured in the AWQ-SCALED domain (ws = W*wscale vs deq), whereas result->recon is in the ORIGINAL weight space (recon = deq * input_scale, AWQ removed, cpp:1320-1324). outlier_vals are f16 of the AWQ-scaled ws, not raw W (cpp:1095). Dispatch normalizes streaming MSE to relative fitness as mse*n/frob2(weights) (tessera-dispatch.cpp:462-464) — the seam should keep raw and normalized values distinct in eval_cache.
- params->use_septq (h:145) and params->use_imatrix (h:144) are NEVER read inside tessera-quant.cpp; imatrix is explicitly voided (cpp:960, 1198). SEPTQ routing is a dispatch-level branch (tessera-dispatch.cpp:317, 2834-2881, 2943) that calls ts_septq_quantize_2d (tessera-septq.h:112-116). ts_expert_eval must branch on use_septq itself; passing it through ts_quantize_2d is a silent no-op.
- Header/definition signature mismatch: the config-parameterized ts_compute_scales is declared with 7 params (h:90-93) but defined with 8 (`float global_amp` last, cpp:393-397). The declared 7-arg overload has no definition — an external TU calling it as declared gets a LINK ERROR. External callers today can only use the legacy 6-arg T640 wrapper (h:82-84 -> cpp:447-453, which forwards global_amp=0.0f and passes `weights` as non-null core). Copy the 8-param definition signature into the spec, and fix the header when introducing the seam.
- ts_pack_tile640 / ts_pack_tile write PLACEHOLDER scales, not fitted ones: unit f16 page scale (cpp:478) and lane flag 127-if-any-nonzero-else-1 (cpp:492). Real scales require the follow-up ts_compute_scales pass (h:69-74). A dequant-scoring path that packs but forgets the refit will dequantize garbage amplitudes.
- Thread-safety/allocation: ts_awq_scale_search uses a `static thread_local std::vector<float> scratch` (cpp:761-762) that grows to R*in_dim floats and persists per thread; everything else allocates std::vector locally per call (no shared state). ts_quantize_mse_streaming allocates its O(in_dim) vectors on every call — a hot Tier-2 loop may want them hoisted into the seam's tensor_ctx.
- Metal behavior: both ts_quantize_2d_ternary and ts_quantize_2d gate Metal on ts_metal_available()==1 && in_dim<=8192 and UPLOAD THE WEIGHTS TWICE per ts_quantize_2d call (ternary step cpp:978-985 releases at 1113-1115; MSE step re-uploads 1262-1269). All Metal failures fall back silently to CPU. Layer-output alpha search (calib_X+ref_output present) always bypasses the Metal grid kernel (cpp:993, 1014). ts_quantize_mse_streaming is pure CPU. A per-expert eval loop through the full path pays 2 uploads per expert unless the seam hoists the upload into tensor_ctx.
- Ternary threshold is a WHOLE-TENSOR global mean(|ws|) (cpp:342-343, 1402): scoring an expert requires slicing exactly at the expert boundary (ts_quantize_3d does weights + ex*out_dim*in_dim, cpp:1484/1523); folding multiple experts into one call changes every expert's threshold and thus its trits.
- Reduction-precision drift: streaming accumulates threshold and MSE sequentially in double (cpp:1389-1402, 1417); the fused path computes the threshold via ts_vec_meanabs (vDSP_meamgv, f32, on Apple; cpp:339-342) and the full-path Apple MSE fold accumulates in f32 (cpp:1300-1327) while the portable branch uses double (cpp:1331-1358). Last-bit MSE differences across paths/platforms are expected ('Only the reduction precision may differ', h:190) — eval_cache comparisons need a tolerance, not equality.
- ts_quant_result_2d has NO default member initializers: best_alpha and mse are indeterminate on a default-constructed result until ts_quantize_2d sets them; ts_pack_ternary_to_tile sets NEITHER (nor recon) — ts_quantize_2d assigns best_alpha itself afterwards (cpp:1222). ts_ternary_tensor by contrast defaults global_amp=0.0f, best_alpha=0.0f, out_dim=0, in_dim=0 (tessera-ternary.h:46-49).
- ts_pack_tile asserts (assert(false)) on TS_PACK_2BIT (cpp:496-501): only TS_PACK_RADIX243 (T640) is implemented; ts_tile_config_t512/t1024 configs (ggml-common.h:244-262) will abort in debug and silently fall through in NDEBUG builds.
- dequantize_row_tessera_t640_with_meta takes PRE-DECODED float page_max_in / lane_scale_in arrays (ggml-quants.h:57-61 — meta decode hoisted out of the per-row loop), NOT the raw u16-f16/i8 arrays stored in ts_quant_result_2d/ts_septq_result; and it knows nothing about the outlier CSR — the caller must decode scales (f16->f32; int8 lane/127.0) and apply the CSR addback itself. The CPU-internal ts_dequant/ts_dequant_rows (cpp:577-676) are static — not callable from a seam in another TU without exposing them.
- Outlier ordering convention: outlier_cols within a row are in residual-magnitude-descending selection order, NOT column-sorted (stable_sort at cpp:1072-1075 sorts by row only, preserving ts_select_repair_residuals' partial_sort order); KV-codec digests over the CSR must treat within-row order as significant.
