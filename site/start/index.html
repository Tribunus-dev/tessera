On-ramp

Build. Run. Load your first model.

A five-minute first pass. macOS first, Linux supported. The full engine is a single CMake build. The Studio app downloads separately.

Step 0

Pick your path.

There are two on-ramps. Most people start with Tessera Studio, the app; you can drop a model in and use it. If you want to quantize your own model, you want the engine on top.

Just run models.

Download Tessera Studio from the App Store. The model library has Gemma 4 12B unified, Qwen 3 TTS, and a small set of Tessera-trained models. Pick one. Chat. Done.

Quantize your own model.

Build the engine from source, calibrate on a corpus, write a Tessera-T640 GGUF. The pipeline runs end to end with one command. This is the on-ramp for engineers and researchers.

Prerequisites

What you need on the machine.

For the engine build:

  • macOS 14+ on Apple Silicon (M1 / M2 / M3 / M4). The ANE prefill needs M-series; Intel macs fall back to the CPU path.
  • Linux x86_64 or aarch64 with CUDA 12+ for GPU, ROCm 6+ for AMD GPU, or CPU-only. ANE is macOS-only.
  • CMake 3.20+, a C++17 toolchain (clang on macOS, gcc 11+ on Linux).
  • Python 3.10+ for the calibration pipeline.
  • A small model to calibrate against (a 1.1B parameter Llama is enough for the smoke test).

For the Studio app: macOS 14+ on Apple Silicon. iOS 17+ on A14+ (iPad Pro M-series or iPhone 12+).

Step 1

Build the engine.

Clone the repo and build llama-quantize. The Tessera pipeline is the default mode; opt back to stock K-quants with --tessera-mode=off.

git clone https://github.com/Tribunus-dev/tessera
cd tessera
cmake -B build -DGGML_METAL=ON
cmake --build build --target llama-quantize -j

The output binary is build/bin/llama-quantize. Linux builds additionally need OpenBLAS for the AWQ-Evolve GA inner loop; the build will print the install command for your distro if it is missing.

Step 2

Calibrate, then quantize.

Pass a model to llama-quantize with a Tessera type and let the pipeline run end to end:

build/bin/llama-quantize \
  --tessera-mode=on \
  --tessera-policy=auto \
  --imatrix \
  --calib-corpus=tessera-cc0 \
  models/tinyllama-1.1b.gguf \
  models/tinyllama-1.1b.tessera-t640.gguf \
  TESSERA_T640

The pipeline runs three stages: calibration (the built-in CC0 corpus, no download step), AWQ policy search (the per-tensor GA), and quantization (the writer). Each stage writes its output to the sidecar. The final artifact is the GGUF; the signed receipt is in the sidecar.

Step 3

Read the receipt.

Run the A/B harness to re-dequantize the artifact through the kernel and compare against the original:

python3 tools/tessera/tessera-ab-harness.py \
  --baseline models/tinyllama-1.1b.gguf \
  --candidate models/tinyllama-1.1b.tessera-t640.gguf \
  --metric t_l2

The harness reports the per-tensor t_l² and the aggregate. The t_l² is the Frobenius distance between the original weight and the kernel's dequant output, normalized by the max weight magnitude. A green receipt is one where the t_l² matches what the policy predicted.

Step 4 (optional)

Install Tessera Studio.

If you just want to run models and skip the quantization pipeline, install Tessera Studio from the App Store. The app ships with a model library you can browse without building anything.

Once installed, open the app, drop into the Library, pick a model, and start chatting. The app handles dispatch (CPU / GPU / ANE), the agent loop, and the hybrid drafters automatically. The flywheel is opt-in; turn it on in Settings if you want your usage to help improve the next model.
